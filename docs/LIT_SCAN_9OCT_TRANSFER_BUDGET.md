# Literature scan, 9 Oct 2026: zero-shot transfer (Claim 1) and budget type as input (Claim 2)

**Scope.** This scan checks two novelty claims made for SPECTRA against prior work. SPECTRA is a frozen generic DRL agent for structured CNN channel pruning that extends NEON (Hirsch & Katz, *Information Sciences* 610, 2022, doi:10.1016/j.ins.2022.07.134). The aim is to gather evidence, not to argue for the claims.

**How each source was verified.**
- Titles, authors and dates come from the arXiv API. Venues come from the arXiv comment, the PDF header, Crossref or Semantic Scholar; the table says which.
- Full texts were downloaded as arXiv PDF or HTML, converted to text with `pdftotext`, and searched. Every quote below is copied from that text. Quotes are only shortened (marked "...") and de-hyphenated across line breaks.
- "Read depth" gives how much of each paper was read: "abstract", "abstract + method section", or "full text (sections X)". For full text, the sections actually read are listed; I did not read every page of every paper.

**Tags.** **[V]** means verified from the source at the stated depth. **[I]** means my interpretation.

## 1. Bottom line

### Claim 1 (transfer)

*"No CNN-pruning paper reports zero-shot transfer of a frozen pruning/allocation policy to unseen architectures (no fine-tuning, no retraining of any agent component on the target)."*

**Verdict: survives only with qualification. As literally worded, one 2025 preprint contradicts it within a single architecture family.**

1. **The closest work** is Liu, Wang & Zhang, *Meta Pruning via Graph Metanetworks* (arXiv:2506.12041, 2025, marked "Under Review").
   - A GNN metanetwork is meta-trained on ResNet-56 models and then applied, frozen, to ResNet-110 on CIFAR-10, and the other way round. Both directions beat the no-metanetwork baseline (Sec. 6.3, Table 5) [V].
   - The authors themselves say "no prior work has done something like this before" (Sec. 4.4) [V].
   - The qualifiers [V]:
     - The learned part rewrites weights. The widths then come from a fixed group-norm ranking at a speed-up set by hand for each architecture (App. F.2).
     - The target net is fine-tuned.
     - Only two architectures, both ResNets, are tested.
2. **Every other CNN result** falls short of zero-shot transfer to an unseen architecture [V]:
   - It updates part of the agent on the target: AGMC retrains its decoder for 100 search episodes; GNN-RL retrains its MLP head.
   - Or it uses the source policy only as a warm start: N2N; Mu et al., TCAD 2024.
   - Or it keeps the architecture fixed and changes only the data or weights: Gonzalez-Sahagun et al., IEEE Access 2024, a "generalist" agent reused from LeNet to LeNet without training on the target; Venkatesan et al. 2020.
3. **Frozen transfer across model families already exists outside CNN pruning** [V]. So the claim needs the scope "structured CNN pruning":
   - DSA (NeurIPS 2024) searches an allocation function once on LLaMA-1-7B and reuses it on other LLMs with no further search.
   - RAMP (arXiv 2026; it is mixed-precision **quantization**, not pruning) transfers a policy trained on Llama-2-7B zero-shot to Mistral-7B.
   - NEON does this for dense networks.
4. **What survives** [I]: a frozen, learned *layer-wise width-allocation policy*, evaluated on *CNN families absent from training*, in one pass, with no per-target search, policy update or per-architecture hyperparameter.
5. **SPECTRA's own evidence is not yet at that level** [I]. Per `docs/CLAUDE_RESEARCH_HANDOFF.md` §3.1, the T1 held-out nets are thin ResNet-56-w4, ResNet-20-w2 and DepGraph ResNet-56, with VGG-19 C100 evaluated outside T1. Their families (ResNet, VGG) are all in the training catalog. So, like Liu et al., SPECTRA currently shows transfer within a family.

### Claim 2 (budget type as input)

*"No prior pruning method has a single trained policy that takes the budget TYPE (params vs FLOPs vs latency) and level as inputs and serves all of them without re-optimisation."*

**Verdict: survives with qualification. It holds for pruning, and only if SPECTRA actually trains and evaluates one agent across budget types.**

1. **No pruning paper found trains one policy that takes the budget type as an input** [V for the papers read]. An arXiv abstract search for pruning together with "budget type", "type of budget" or "resource type" returned no hits.
2. **The closest analogue is in NAS, not pruning:** MODNAS (Sukthanker et al., ICLR 2025) [V].
   - One MetaHypernetwork is conditioned on a device embedding and on a preference vector over the objectives: accuracy and latency, with energy added in a three-objective experiment.
   - It produces architectures for new devices and preferences with no further search.
   - [I] These are soft trade-offs between objectives, not hard budgets. It searches a supernet space rather than pruning a given trained net.
3. **Conditioning on the budget *level* of one fixed type is established and not novel** [V]:
   - CACP (IEEE SPL 2021) does it for CNN channel pruning, with the compression rate as input.
   - SGNAS (CVPR 2021), Flextron (ICML 2024), PPF (2025) and FastForward (2025) do the same in other settings.
   - L2A (2026) folds deadline, queue and memory signals into one scalar budget.
4. **Multi-budget methods either re-optimise or are type-agnostic** [V]:
   - They re-optimise per budget type: ChipNet (four budget types), BAR, AMC, EagleEye.
   - Or they re-run a search per constraint on one shared supernet: MetaPruning, OFA.
   - Or they read every budget type off one greedy path whose order ignores the type: AutoSlim.
5. **Whether SPECTRA meets the claim is open** [I].
   - The code has a params/FLOPs flag (`src/plan_agent.py` line 33 `BUDGETS = ("params", "flops")`; docstring at line 465).
   - This scan did not check whether one trained agent has been evaluated on both budget types on held-out nets.
   - If it has not, Claim 2 can only be written as future work.

## 4. Implications for the thesis wording

### 4.1 Claim 1 (transfer)

**Do not write any of the following.**
- "First frozen/generic pruning agent." NEON did this for dense nets, and Gonzalez-Sahagun et al. 2024 reuse a "generalist" CNN compression agent, from LeNet to LeNet, without training it on the target.
- "First zero-shot transfer of a learned allocation policy" without the scope "structured CNN pruning". DSA and RAMP do this for LLMs.
- "First to prune unseen CNN architectures with a frozen learned component" when the held-out nets are from training families. Liu et al. 2025 does this frozen, from ResNet-56 to ResNet-110, and explicitly claims priority.

**Strongest defensible sentence, given today's evaluation (held-out nets within training families):**

> "To our knowledge, SPECTRA is the first structured CNN pruning method in which a learned layer-wise width-allocation policy, trained once offline on a catalog of CNNs, is applied frozen to unseen networks in a single forward pass, meeting the parameter budget exactly with no per-target search, policy update or architecture-specific hyperparameter. Prior CNN transfer results update part of the agent on the target (AGMC: decoder, 100 search episodes; GNN-RL: MLP head), use the source policy as a warm start (N2N; Mu et al., 2024), keep the architecture fixed (Gonzalez-Sahagun et al., 2024; Venkatesan et al., 2020), or transfer a frozen weight-editing metanetwork whose widths are then set by a fixed criterion at hand-tuned speed-ups (Liu et al., 2025)."

**Caveat on "no architecture-specific hyperparameter".** This phrase covers the agent only. `docs/CLAUDE_RESEARCH_HANDOFF.md` notes that the fine-tune learning rate for a held-out net is currently set per job: lr 0.1 for full-width nets, lr 0.01 for narrow ones. Either state that rule as a fixed recipe, or limit the sentence to the agent.

**Stronger sentence, available only after a leave-one-family-out experiment.** Add: "...including CNN families absent from its training set (e.g., trained without DenseNet, evaluated on DenseNet)." Cite DSA, RAMP and NEON as the analogues outside CNNs.

**Experiments that would strengthen Claim 1.**
- **E1. Leave one family out.** Retrain the agent on three of the four families (ResNet, VGG, MobileNetV2, DenseNet) and evaluate frozen on the fourth, at matched κ. For each fold, report the frozen agent against:
  - uniform and sensitivity heuristics;
  - a per-target search baseline with an equal evaluation budget (random strategies plus adaptive-BN scoring, in the style of EagleEye);
  - the same agent fine-tuned on the target, as an upper bound.
- **E2. A family in no training fold.** For example ShuffleNetV2, ResNeXt, RegNet or EfficientNet-B0 on CIFAR. Evaluate frozen.
- **E3. Count target-side cost.** Report the number of target evaluations used to choose the plan. It must be 0 for "zero-shot": use the mean or greedy plan. If K sampled plans are scored on target data and the best is kept, that is per-target search and must be called so.
- **E4 (optional). Reproduce Liu et al.'s protocol** (ResNet-56 to ResNet-110, CIFAR-10, Table 5 of arXiv:2506.12041) so the in-family comparison is direct.
- **E5. Dataset shift with the architecture fixed** (C10 to C100 or SVHN). This separates SPECTRA from the Gonzalez-Sahagun kind of result.

### 4.2 Claim 2 (budget type as input)

**Do not write any of the following.**
- "First budget-conditioned pruning policy." CACP (2021) for CNNs, and PPF, FastForward, Flextron and L2A in other settings, already condition on the budget level.
- "First to serve several budget types from one trained model" without the qualifier "as an explicit input to one policy, without per-budget search". MetaPruning, OFA and AutoSlim serve several types from one trained artifact through search, or through one type-agnostic path.

**Strongest defensible sentence.** Only use it if one agent has been trained and evaluated across types:

> "To our knowledge, no prior pruning method trains a single allocation policy that receives the budget type (parameters vs FLOPs) together with its level as explicit inputs and returns, in one forward pass and without per-budget search or optimisation, an allocation that meets that budget exactly. Budget-conditioned pruners condition on the level of one fixed budget type (CACP; Flextron; PPF; FastForward; L2A, which folds several runtime signals into one scalar). Multi-budget pruners re-optimise per budget type (ChipNet; BAR; AMC; EagleEye). Supernet methods either re-run a search per constraint (MetaPruning; OFA) or read all budget types off one type-agnostic greedy path (AutoSlim). The closest type-aware conditioning we found is in NAS: MODNAS conditions one hypernetwork on a device embedding and a preference vector over objectives such as accuracy, latency and energy, as soft trade-offs rather than hard budgets."

If SPECTRA has only been trained and evaluated with parameter budgets, write it as future work instead: "the gap exists; SPECTRA's state already carries a budget-type flag".

**Experiments that would strengthen Claim 2.**
- **F1. One mixed-type agent.** Train one agent on a mix of params and FLOPs budgets: a type token plus κ, decoded by bisection on the matching cost model. Evaluate it frozen on the held-out nets **at equal params and at equal FLOPs**.
- **F2. Specialists.** Compare against two specialist agents (params only, FLOPs only) trained with the same compute. The single agent should be within seed noise of each.
- **F3. Wrong-type ablation.** Feed the wrong type token while decoding against the true budget. The accuracy drop measures how much the type input matters. Also report how far the per-layer allocations differ between types, for example the L1 distance between width-ratio vectors. [I] One would expect FLOPs budgets to cut early high-resolution layers more, and params budgets to cut late wide layers more.
- **F4. Type-agnostic baseline (AutoSlim style).** Use one fixed ordering or plan, decoded by each type's cost model. If F1 does not beat F4, type conditioning adds nothing.
- **F5. Level generalisation.** Test κ between and beyond the training grid. CACP, for comparison, trained on a discrete set of rates.
- **F6 (stretch). A third type.** Latency from a device lookup table, or activation volume as in ChipNet and BAR, so that "type" means more than a binary choice. A zero-shot held-out type would be a much stronger claim and is likely to fail; report it either way.

### 4.3 Design-level prior art to cite next to the method description

These are not part of Claims 1-2. The method chapter should cite them so it does not imply that the mechanism itself is new.

- **Single-step "contextual bandit" RL with deterministic exact-budget decoding.** FastForward Pruning (arXiv:2511.18977, Sec. 2.1) maps per-layer scores to an exact budget with a deterministic function.
- **A plan-level policy that emits the whole allocation in one call, trained with a group-relative baseline.** HiPP-Prune (arXiv:2603.06270, Sec. 2.4, 2.6; GRPO). This is close to SPECTRA's K-plan shared-mean baseline.
- **Exact budget satisfaction by bisection.** ChipNet (Sec. 3.4, binary search on the cutoff). AMC and CACP limit the action space so that the budget is met.
- **A transformer controller over per-layer meta-features.** ARLP (KBS 2024, abstract).

[I] SPECTRA's distinct contribution is not these mechanisms. It is (a) the frozen transfer across architectures and (b), if implemented and evaluated, the budget-type input.
