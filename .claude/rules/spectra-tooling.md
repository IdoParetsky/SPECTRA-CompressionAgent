# Tooling on this Windows laptop (learned 9 Oct 2026)

**Git from PowerShell 5.1.** It mangles double quotes in native arguments, so `git commit -m "..."` with quotes fails into bogus pathspecs. Write the message to a file and run `git commit -F <file>`. A non-zero exit after `git push` is usually stderr progress; confirm with `git ls-remote origin refs/heads/master` against `git rev-parse HEAD`.

**Line endings.** `core.autocrlf=true`: shared docs are CRLF in the working tree (queue, runbook, mail, `CLAUDE.md`, tracker, `src/`); the ledger is LF. After an edit, count bare LF in a CRLF file and keep it at 0.

**Your own hunks only, without `git add -p`** (interactive commands are unavailable here). When the other agent has unstaged edits in a file you must commit, stage a constructed blob. Take HEAD's version plus only your hunk, in LF, `git hash-object -w <that file>`, then `git update-index --cacheinfo 100644,<sha>,<path>`. Check `git diff --cached` before committing. The working tree keeps both agents' edits.

**Cluster.**
- Scripts run with `powershell -NoProfile -File scripts/rexec.ps1 -File <script.sh>`. Filter its noise with `Select-String -NotMatch "NativeCommandError|CategoryInfo|FullyQualifiedErrorId|At C:|^\+ |^\s*$"`.
- From Git Bash, use `ssh -o BatchMode=yes -o LogLevel=ERROR bgu-slurm '<cmd>'`.
- Uploads go by `scp <file> bgu-slurm:/home/paretsky/scratch_audit/_up_<name>`. Deploy scripts strip CR and check each upload's `git hash-object` against the local blob before overlaying a new tree.
- CPU tests on the login node: the user slice is capped at 4 CPUs and 8 GB, so set `OMP_NUM_THREADS=4 MKL_NUM_THREADS=4`, and run anything over a minute detached (`nohup … &`, output to a file); an interactive ssh session can drop mid-run (T2's tests, 10 Oct). Run one test file per pytest process, under `setsid nohup`: a combined run of eleven files died silently after about 4 min with no OOM and no exit code (10 Oct 18:27), while the same files passed one per process.

**Write files safely (learned 10 Oct 17:15).** Compute a file's new content in full before opening it for writing, then write a temp file and `os.replace` it over the target. `open(p, "wb").write(f(x))` truncates `p` before `f` runs, so an exception in `f` leaves the file empty. That emptied the shared queue and lost ops' unstaged stamps. Assert every anchor before any write.

**Disk quota (learned 11–12 Oct).** `/home/paretsky` is NFS with a per-user quota that `quota` does not show. Use sits close to it (about 127 GB on 12 Oct), so probe with a small write before a wave. A job that starts over quota dies in seconds with exit `0:53` and no log, or finishes COMPLETED without its rows. NFS can report `Disk quota exceeded` for a write that still lands. `scripts/_tmp_s12oct_watch.sh` exits 6 on a failed write. Snapshot directories (`traj_models`) are the bulk that can be freed: back them up first (Drive once Ido sets up an OAuth remote, else the laptop) and delete only after a per-file check.

**Preemption and stuck jobs (learned 12 Oct).** The cluster preempts our GPU jobs (`PREEMPTED`, "CANCELLED … DUE TO PREEMPTION"; three times on 12 Oct). The submit scripts set `Requeue=0`, so a preempted job never comes back: the watcher exits 3, and science registers the reason in the queue row and resubmits that net and seed only (the `resub` / `net:var:seed` modes). A node can also lose DNS to the controller (`Unable to resolve "slurm-master"`), and a job that finished its run then stays RUNNING. Its log's "Run finished in" line is the evidence, and the readers count it as complete with a printed note. `bgu-slurm` reaches more than one login node, so `/tmp` is not shared between ssh sessions: keep files in home.

**Backslashes in shell heredocs (learned 12 Oct).** Through this Bash tool, even a quoted heredoc turns `\\` into `\`, so a Python literal `"C:\\x\\tree"` arrives as `"C:\x\tree"` and `\t` becomes a tab. Write any script that holds a Windows path with the Write tool.

**Waiting is event-driven (Ido, 10 Oct).** Never foreground-sleep or poll in a loop in the main tab. Wait with a background Bash until-loop over `sacct` that exits on a terminal state (COMPLETED, FAILED, CANCELLED, TIMEOUT, OUT_OF_MEMORY, NODE_FAIL, PREEMPTED); it wakes the session once. Let it exit early on the first non-COMPLETED terminal state, so a failure is seen at once. A timed wake (a background `sleep` to a clock time) is fine for a promised report. A watcher must treat a dead link as an event: exit after about four consecutive polls that cannot reach the cluster (`scripts/_tmp_s11oct_watch.sh`, exit 5), say so in the brief and the mail, and then wait on a link check. The BGU VPN dropped twice on 11 Oct, and a watcher that retried silently lost a working day of reads. Cells that have a preemption guard need a watcher that follows the newest job per cell, read from the manifest on the cluster (`scripts/_tmp_s13oct_watch2.sh`). Otherwise every resubmit the guard makes wakes the session. A preempted job that its guard has not resubmitted within three polls still wakes it; trains have no guard, so a preempted train always does. A gate's verdict file has its own watcher (`scripts/_tmp_s13oct_gatewatch.sh`).

**Smokes and priorities (learned 10 Oct).** A smoke that exits 0 can still have failed: the runner catches a per-network exception and finishes with status 0, so afterok releases the dependents (T0-F2's first eval smoke). Read each smoke's start-check lines before any cell runs: submit the cells held (`scontrol hold`) and release them after the read. Slurm's age factor, counted from eligibility, outweighs nice gaps of a few units, so nice alone does not order a long queue; re-nice or hold explicitly. Check with `sprio -u paretsky` before re-nicing. On 13 Oct, for jobs pending under an hour, the age component was 0 and priority followed nice exactly (about 91 − nice), so the nice values already set the order. By 14 Oct 04:25 our fair-share had run down: every pending job of ours sat at priority 1, nice had no effect, and ties went to submission order. To put a critical-path cell first, hold the later-needed cells and release them by a login-node script (`scripts/_tmp_s14oct_p25_yield.sh`), and record it in the queue row. A lighter tool also works here (the scheduler has `enable_user_top`): `scontrol top <ids>` lowers the nice of our other pending jobs and lifts the named ones above them. On 18 Oct it moved 4 audit jobs from a tie at priority 41 to the head of our queue. Check with `squeue -u paretsky -t PD -o "%Q %y %j"`; the first attempt, on 17 Oct, showed no change. `SBATCH_HOLD=1` does not hold jobs submitted through `scripts/submit.sh` (HEAD-F, 12 Oct): run `scontrol hold <id>` right after each submit. That hold can still lose the race when GPUs sit idle: on 16 Oct 03:09, 3 of LIT-B's 39 cells started before their hold landed. So also give held cells a dependency on their smokes (`SPECTRA_DEPENDENCY=afterany:<smoke ids>`): no cell can then start before the gate has read, and the hold stays the gate's switch. A gate on a network new to the pipeline also checks its origin accuracy (the "acc X ->" of the TRAJ line): akamaster's ResNet-110 loaded at chance (0.103) and still passed every landing and masking check (16 Oct). A gate's pattern is code, and three gates have failed on their own (THRU, PRE-W1, REC-W1). Match the size label first and fall back to `val_best` only when the size line is absent: a regex alternation such as `(size_param0.25|val_best)` returns whichever line comes first in the log, and `val_best` usually does (REC-W1, 17 Oct 08:06). When a gate holds cells, read the smokes' logs by hand before calling the cut a failure. The same holds for saved files: an eval fine-tunes, and under `SPECTRA_EVAL_SAVE_FINAL` saves, every candidate, `val_best` included. So choose a saved model by the label in its `.json`, never by the first file a glob returns. TS's first gate (20 Oct 02:36) chained stage 2 from `val_best` models at 0.88–0.997 kept.

**No log dumps in the main tab (Ido, 10 Oct).** Readers write their full output to a scratchpad file; the tab shows the call lines and compact tables only. Never paste a raw log, a whole reader output or a subagent transcript.
